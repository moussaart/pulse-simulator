2. Core Engine — Module Breakdown

The core engine is the heart of PULSE. It runs the physics simulation independent of the GUI and API layers.

📡

UWB Channel Model

src/core/uwb/

Implements the IEEE 802.15.4a Saleh-Valenzuela model. Generates realistic Channel Impulse Responses (CIR) with multipath, path loss, shadowing, and NLOS conditions.

🎯

Localization

src/core/localization/

Contains all position estimation algorithms: Trilateration, EKF, UKF, Adaptive EKF, NLOS-Aware AEKF, Particle Filters, and the plugin system for user-created algorithms.

🏃

Motion Model

src/core/motion/

Generates tag trajectories: circular, figure-8, random walk, CSV import, and custom drawn paths. Also handles moving obstacles.

🔋

Energy Model

src/core/uwb/energy_model.py

Duty-cycle based power estimation with hardware profiles (DW3000, NXP SR150). Supports SS-TWR and DS-TWR ranging modes.

Step-by-Step Execution

  1. Tag Position Update — The motion model advances the tag position based on the selected trajectory pattern and time step (default 5ms).
  2. Channel Model — For each anchor-tag pair, the UWB channel model computes:
    • Path loss (distance + frequency dependent)
    • Log-normal shadowing
    • Multipath CIR via Saleh-Valenzuela model
    • LOS/NLOS condition (based on obstacle intersection)
  3. Ranging — Time-of-Flight distance measurement is derived with:
    • Gaussian noise bounded by CRLB (from SNR)
    • NLOS positive bias (when direct path is blocked)
  4. Localization — The selected algorithm processes the noisy range measurements to estimate the tag position.
  5. Output — Results are sent to GUI display, data collection buffer, and/or RL agent socket simultaneously.

4. AI Training Architecture

PULSE provides two modes for AI/ML integration — online (real-time RL) and offline (batch data collection).

    API->>SIM: Apply anchor selection
    SIM->>SIM: Next simulation step
    Note over SIM,AGT: Loop continues...
🔄

Online Training (RL)

The AIGymServer exposes a TCP socket. An external agent (PyTorch, Stable Baselines) connects, receives observations, sends actions (anchor selection), and the simulator applies them in real-time.

💾

Offline Training (Data)

The TrainingDataAPI hooks into the simulation loop to collect samples into a buffer. Data can be exported as NPZ, CSV, JSON, or PyTorch Datasets for supervised learning.

Scope Isolation

The AITrainingAPI creates a training-local copy of configuration. All SET operations (changing anchors, filters, energy profiles) modify only the training copy — the main simulation state is never affected.
